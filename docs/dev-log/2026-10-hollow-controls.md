# 2026-10-18-空壳控件（只有样式、点了没反应）

> 现象：gallery 上大量控件「只有样式」—— 点了没有任何变化。开发者对示例项目
> 最致命的差评，而它**编译过、画面正常、其余门禁全绿**：key 在树上
> （`every_class_name_*` 过）、元素可达（`every_element_is_*` 过）、命中测试通过
> （`hit_test_*` 过），唯一缺的是 `Gallery::click` 里没有对应分支 —— 或者控件层
> 根本没把子项标成可交互。

## 排查

写了一个审计脚本：扫全部页面发的控件 key × `click()` 里已接线的字面量/前缀分支，
列出「在树上但没人认」的 key。**第一次跑就列出 30 个**，随后用一条新门禁
（见「结论」）把它们归成四类：

| 类别 | 例子 | 处理 |
|---|---|---|
| key 拼错（真 bug） | `combo-material` vs `combo:material` | 改 `click` 认页面真发的那个 |
| 分派漏接 | `state-switch`、`theme-mica`、`lang:en`、`tool:*`、`feedback` | 补分支 |
| 状态绑错字段 | `switch:master` 绑 `wants_dark`，分派却改 `switch_on` | 合并到同一分支 |
| 控件层无可交互节点 | 表格数据格 / 日期格 / 时刻项 / 色格 / 翻页圆点 | 加 `INTERACTIVE` |
| 展示型（正确） | 滑条、文本输入、进度条、窗口按钮、NavItem 外观 | 白名单 + 注释 |

三处**更隐蔽**的：

1. **`combo-material` 少一个冒号**。`click` 认 `combo:material`，页面发
   `combo-material`。不崩、不报错，ComboBox 一直显示第一项 —— 看起来就像
   「这是个默认值」，而不像「点了没反应」。
2. **`spin_text` 的查表只映射 0..=10，其余回落 `"42"`**，而默认值就是 42。
   于是点 ＋/− 状态**真的变了**（`spin` 从 42 到 43），显示的文本纹丝不动。
   「状态变了但视图没变」比「状态没变」更难发现 —— 它骗过了「点一下看状态」的
   检查。修法是把值域收进表内（默认 7，0..=20），三处（边界/默认/表）同步。
3. **expander 的可点节点 key 是内部名 `header`**（`card::expander` 与
   `collections::setting_expander` 都如此）。同页两个 expander 就撞名，输入回调
   只报 `header`，应用无法分辨是谁被点了 —— gallery 的 `set-exp` / `set-adv`
   分支**永远收不到点击**。修法是把可点节点的 key 改成控件自己的 key。

## 排除的假设

- **「滑条点了没反应是漏接」** —— 不是。core 的 `InputState` 没有连续指针位置，
  拖动无法表达；能给滑条的只有「点击轨道跳值」这种假动作。归入展示型白名单，
  并在页面上标注 `(display)`。
- **「表格/日期/时刻/色格是数据展示，不该可点」** —— 在 gallery 里它们看起来就是
  可点的（成组的小方块），点了没反应正是投诉的形状。**控件层**给它们加
  `INTERACTIVE`（不换 tag：样式表按类型选择），选中态由应用持有，与 `list_view`
  的行同一模式。
- **「白名单可以长一点没关系」** —— 有关系。白名单是「哪些可交互元素点了没反应」
  的完整清单，每多一项就多一个骗过门禁的空壳。压到 18 项，每项写清为什么不接。
- **「几何门禁能发现『内容装不下被裁掉』」** —— **错**，这是本轮最大的误判。
  测试里的 `Context::new(&theme)` 没有文本引擎（`engine: None`），文本按兜底度量
  排版，行高比真实字体**小得多**。实测：basics 族在真实字体下色板掉出客户区
  100+px、Avatar 整节被裁，而 `hit_test_agrees_with_the_painted_rects` 用无字体
  布局量出来「稳稳在框内」。判据必须与 `--dump-cpu` 同源 —— 改用
  `zephyra_fx::from_system_font()`。

## 结论

1. **`click` 的分派补齐**：前缀分支（`act:` / `list:` / `td:` / `dpc:` / `sw:` /
   `swatch:` / `lang:` / `tool:` …）+ 常量表查回 `'static`（key 是运行期 `&str`，
   不能直接存进 `&'static str` 字段）。
2. **触发类按钮的回显放在外壳页头**（`shell.rs` 的 `last-action`），不放各页页首：
   放页首的话，layout / menus 章的按钮改的是**看不见的树**，与「没接线」无法区分。
3. **控件层三处修正**：expander 可点节点 key；表格格 / 日期格 / 时刻项 / 色格 /
   翻页圆点加 `INTERACTIVE`；`swipe_view` 的元组从 `(id, label)` 改成
   `(title, desc)`（旧形状把内部键名 `swipe:0` 当正文画出来）。
4. **参考层 9 族 → 10 族**：真实字体下 Collections 四节装不下（页高 838，
   Avatar 整节掉出），把 SwipeView 单列一族 `paging`；色板 4×4 → 8×2；
   basics 的文本输入与值输入各并成一行。每族现在都留有余量。
5. **`--list-families` / `--family <n>`**：参考页族化之后 `--route reference`
   只出第 0 族，另外九族在静态出图里**看不见** —— 补上开关才能逐族核对。

## 门禁

| 门禁 | 钉住什么 |
|---|---|
| `every_interactive_key_is_wired_or_whitelisted` | 全路由 × 全族扫树收集 `INTERACTIVE` key；每个 key 在**三个扰动世界**里真点一遍，比较点击前后的树形状指纹（类型/key/分类名/**文本值**）。无差异且不在白名单 ⇒ 红 |
| `hit_test_agrees_with_the_painted_rects` | 改用真实系统字体布局，并逐**族**量：可交互节点的矩形必须落在客户区内且命中链正确 |
| `reference_page_has_all_families` | 族数写死（改族必须红一次，逼人确认新族一屏装得下） |

**「扰动世界」是这条门禁的关键**：选中型控件点击**当前选中项**时状态本来就不
变（正确行为），而默认 Gallery 恰好停在各控件默认项上 —— 直接点会得到假阴性。
两个相位把每个选择器挪到不同候选，第三个世界换一条路由（覆盖「点当前路由的
导航项」这种天然 no-op）。首轮 30 个 key 里有一半是这种假阴性，没有扰动就会
教人去删真实的分派。
