> 而 core 两者都不能动画。本轮把那笔账结掉。

## 0. 动手前先确认的事实（都来自读码，不是推测）

| 事实 | 位置 | 后果 |
|---|---|---|
| `props::OPACITY` **已存在**，且是 `inheritable` | `props.rs:76` | 不用新加属性 |
| zstylec **已映射** `opacity` | `props_map.rs:58` | 静态半透明容器现在就能写 |
| `paint` 只把 opacity 用在 **image tint** | `paint.rs:554` | 背景 / 描边 / 文字 / 图标外的 Quad 全都不透明 |
| `property::resolve(store, key, None)` —— **没有任何生产代码传过非 `None` 的 `inherited`** | `style.rs:267` | `inheritable` 标记**没有接线**；`opacity()` 取的是**本节点**的值，不是祖先链的乘积 |
| `Color::with_alpha(factor)` 是**相乘**不是替换 | `core.rs:163` | 可以安全地叠在已有的半透明底色上 |
| `glyph_quads(shaped, origin, style)` 纯函数、无缓存 | `text/mod.rs:379` | 传平移后的 `origin` 是**免费**的 |
| `IconSet::cached_mesh(icon, rect)` **按 rect 缓存**，实测 50 µs/图标 | `paint.rs:745` | 每帧平移 rect 会让缓存次次落空 ⇒ 必须**先按未平移 rect 三角化，再平移顶点** |
| `Command::Text` 的 `glyphs` 在 core 侧是空 Vec（字形整形是宿主的活） | `paint.rs:152` | 画面的文字差异只能在宿主的字形层看到（与 [`i18n.md`](i18n.md) §7 同一笔记） |

**由此定的实现口径**（与"源码零外观"不冲突）：

- **不透明度与偏移都在 `render_rec` 里沿树累加**，不依赖属性继承。
  理由：`inheritable` 没接线（见上表），去接它会牵动 `text_color` 等一整批属性，
  那是独立一轮。绘制趟自己累加是**自洽且正确**的做法：嵌套容器天然相乘/相加。
- **`translate` 必须是纯绘制属性**（`affects_layout() == false`）——
  这正是"绘制时插值偏移"的定义：动的是画面，不动布局盒、不动命中测试。

## 数字的出处（逐个交代）

| 数字 | 出处 |
|---|---|
| 333 ms（入场时长） | 官方动效表「直接入口 / 现有元素」的时序档，`motion/` |
| (0.55, 0.55, 0, 1) | 官方「点到点」缓动（现有元素入场用这条，不是 (0,0,0,1)） |
| 8 档 | 本仓取舍：档位越多越平滑，但每档都要在样式表里有一条规则（门禁会查） |
| 起点 opacity 0 → 1 | 官方：页面刷新 =「向上滑动 + 淡入」 |
| 起点 translate-y **+N px** | ⚠️ **官方材料没有给像素距离**。方向有（向上滑），距离没有。见下 |

### 那个没有出处的数字

`animation.md` 的官方表给的是**时长与缓动**，`page-transitions` 给的是**方向**
（向上滑动 + 淡入）。**位移多少像素，官方两处都没有**。

处置：取一个小的整数值并**在代码里显式标注它不是官方数字**，同时门禁钉住它不许被悄悄改掉。
选小的理由：位移越大越容易在不支持动画的环境里暴露成"页面错位"，而 8 px 在 1400 宽的
内容区上是看不出来的量级 —— 动画要的是"有响应"，不是"看得见的位移"。

## 已知不做（记账）

| 不做 | 为什么 |
|---|---|
| 属性继承（`PropertyKey::inheritable` 接线） | 会牵动 `text_color` 等一整批属性，是独立一轮。本轮用绘制趟累加绕开，语义等价且不扩大影响面。 |
| 退场动画 | 官方：直接退出「**始终结合淡出**」，且只有 167 ms；而本仓的路由是**换声明**不是换层，退场需要旧页面留在树上 —— 那要 core 支持"两个页面同时在场"。记账见 [`animation.md`](animation.md) §5。 |
| 弹性入（3 关键帧） | 需要**时间线**（多段时长拼接），而 `anim` 只有单段。记账同上。 |
| 控件级微动效（hover 缩放等） | 同上：档位机制能用，但没有官方像素数字可用。 |

### 实测证据（不靠目视）

三帧 dump 的像素比对（每 3 像素采样一次，共 374067 个颜色通道）：

| `--enter-ms` | 通道均值 | 与 0 ms 的差异 |
|---|---|---|
| 0 | 96.781 | — |
| 120 | 89.883 | 137386 个通道不同 |
| 333 | 96.781 | **0 个通道不同** |

均值变低是因为半透明叠在深色底上。第三行更重要：`enter-8` 撤掉之后，
画面与**完全不带动画**的那一帧逐通道相同 —— 动画不留下任何残留。

### 过程中被自己的测试抓到并修掉的三个缺陷

1. **`descend` 只加到子节点**：本节点自己的不透明度与位移被漏掉。
   症状是"容器背景不动、里面的东西动了"。四条 opacity 门禁里两条立刻红。
2. **分类名永不撤掉**：`anim::step(1.0)` 返回 `Some(8)`，于是页面永远停在
   `.enter-8` 的 0.91 不透明度上 —— 画面蒙一层灰且**没有任何报错**。
   由 `档位走到头之后不再有分类名` 抓到。
3. **`enter_ms` 在换路由那一帧把本帧的 dt 也加了**：症状是"切页之后动画
   几乎不播"（反复切页时 `enter_ms` 已经很大）。改成**先归零再决定是否累加**。

### 一个测试方法论上的坑

`零位移不重新分配顶点` 用 `Arc::ptr_eq` 断言"零位移时顶点内存被复用"。
第一版**单跑绿、全量跑红** —— `icon::builtin()` 是进程级共享缓存，
而 `cache_mesh` 对**同键**是**覆盖**，别的线程渲染图标就把我们的 `Arc` 换掉了。

判据从"两次渲染共用一块内存"改成"**每个测试一份私有 `IconSet`**"。
教训：`ptr_eq` 这类判据要求被测对象是**独占**的；共享可变状态会把断言的对象换掉。

### 新增的调试开关

`gallery --dump-cpu --enter-ms <n>`：把入场时钟拨到指定毫秒，配 `--route`
就能截到任意一档的画面。没有它的话 dump 路只渲染一帧，而动画只在"换路由后的
333 ms 内"存在 —— 于是永远只能看到放完之后的样子。
