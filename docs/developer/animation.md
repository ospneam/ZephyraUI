# 动画 —— 官方依据与本仓实现口径

> 出处（2026-10 查）：<https://learn.microsoft.com/zh-cn/windows/apps/design/motion/>

## 1. 官方的缓动与时長表（逐字抄录）

该页「动画属性」一节：

| 用途 | 定义 | 缓动 | 时序 | 可作用属性 |
|---|---|---|---|---|
| 直接入口 | 快入 | 三次方贝塞尔 **(0, 0, 0, 1)** | 167 / 250 / **333** ms | 位置、刻度、旋转 |
| 现有元素 | 点到点 | 三次方贝塞尔 **(0.55, 0.55, 0, 1)** | 167 / 250 / **333** ms | 位置、刻度、旋转 |
| 直接退出 | 快出 | 三次方贝塞尔 **(0, 0, 0, 1)** | **167** ms | 位置、缩放、旋转（始终结合淡出） |
| 平缓退出 | 软出 | 三次方贝塞尔 **(1, 0, 1, 1)** | **167** ms | 位置、比例 |
| **最低限度** | 淡入 + 淡出 | **线性** | **83** ms | **不透明度** |
| 强大入口 | 弹性入（3 关键帧） | (0.85,0,0,1) / (0.85,0,0.75,1) / (0.85,0,0,1) | 167 / 167 / 333 ms | 位置、比例 |

三条不能自己拍的东西：

1. **83 ms 线性专用于不透明度** —— 不是"约 80 ms 的什么缓动都行"；
2. **点到点用 (0.55,0.55,0,1)**，与直接入口的 (0,0,0,1) 是两条不同曲线；
3. 直接退出「**始终结合淡出**」—— 位置/缩放动画不得单独退出。

页面切换另有专页：<https://learn.microsoft.com/zh-cn/windows/apps/design/motion/page-transitions>
（官方示意：顶层页面**从底部向上滑动**，顶级页与子页之间**左右滑动**）。

## 2. 本仓把动画放在哪一层

动画是**状态**，所以它属于应用层（与 hover / pressed / route 同层），不属于控件层。
`View::on_input(&mut self)` 每帧被宿主调一次，它就是动画的 tick ——
这一条决定了整套实现不需要给 core 加"每帧回调"。

```
宿主每帧开头  →  sync_input(): InputState { hovered, pressed, pointers, viewport, scale, dt_ms }
                        ↓
Gallery::on_input(&mut self)  →  推进自己的动画时钟（&mut self 就在这里）
                        ↓
Gallery::view(&self)          →  按当前进度造树（含分类名）
```

## 3. **离散档位**而不是连续插值

这是本仓做动画唯一合规的形态，原因是一条既有规矩：

> `tests::gates::the_whole_tree_writes_no_appearance_in_source` ——
> 源码不许把外观（颜色 / 圆角 / 间距 / alpha）写进属性。

于是动画的**进度**（0..1）在代码里，进度**映射到的外观值**必须仍在 zstyle。
做法是把进度量化成 N 档（[`anim::STEPS`]），代码只发"第几档"这个分类名：

```rust
// 代码只决定"第几档"——外观值全在 zstyle。
.styles(anim::step(self.enter_ms, anim::ENTER_MS).then_some(...))
```

这与"状态也是分类名"（commit `0f7a840`）是同一条模式的延伸：
hover 是 `.hovered`，动画是 `.enter-3`。

⚠️ 档位数是**取舍**，不是免费：
档位越多越平滑，但每档都是一个分类名，而分类名必须在样式表里有对应规则
（`every_class_name_the_source_emits_exists_in_the_stylesheet` 会查）。
本仓取 [`anim::STEPS`] = 8：83 ms ÷ 8 ≈ **10.4 ms 一档**，仍在官方
"至少 60 fps"的响应式要求内（触控页原文：「动画还应至少保持 60 fps」）。

## 4. 缺口（**已在本轮结清**，这里保留原判断）

上表的官方动作全是**不透明度**与**位置**。core 此前两者都不能动画：

| 能力 | 当时 | 现在 |
|---|---|---|
| 不透明度 | `DisplayList` 的 `Quad.fill` 是 `Color`（含 alpha），但容器没有"整体 alpha" | ✅ `props::OPACITY` 落到**背景 / 描边 / 文字 / 图像 / 图标**五处，并沿父子链**相乘** |
| 位置 | 布局算出 rect，绘制直接读 rect | ✅ 新增 `props::TRANSLATE_X/Y`，绘制时加一个**不影响布局盒与命中测试**的偏移 |

两条能力由 `zephyra-core/tests/paint_transform_tests.rs`（15 条）钉住，
接线由 `ZephyraUI/tests/anim_wiring_tests.rs`（7 条）钉住，
过程与取舍见 [`task-anim-wire.md`](../dev-log/task-anim-wire.md)。

### 4.1 当时写的结论为什么是对的

> 所以本轮只落地**地基**（缓动求值、时钟、档位映射，全部可单测），
> 把接入留到补上上述能力之后。这不是"没做完"的借口 ——
> 在缺能力的情况下做出能跑的东西，只能靠把进度映射到**颜色/圆角**上伪装，
> 而那种假动画一眼能看出来，比没有更糟。

补上能力之后回头看，这段判断成立：伪装路线（比如用 `corner-radius` 表示进度）
确实能立刻"动起来"，而它与官方表的「可作用属性：不透明度 / 位置」毫无关系。

### 4.2 仍然缺的

| 缺 | 为什么 | 记账 |
|---|---|---|
| **退场动画** | 官方：直接退出「**始终结合淡出**」，且只有 167 ms。而本仓的路由是**换声明**不是换层 —— 退场要旧页面**留在树上**，需要 core 支持"两页同时在场"。 | `task-anim-wire.md` §「已知不做」 |
| **弹性入**（3 关键帧） | 需要**时间线**（多段时长拼接），而 `anim` 只有单段 `progress`。`BOUNCE_MS` 只是三段时长之和，没有分段求值。 | 同上 |
| **控件级微动效** | 档位机制够用，但没有官方像素数字可用（见 `task-anim-wire.md` §「那个没有出处的数字」）。 | 同上 |
| **属性继承接线** | `PropertyKey::inheritable` 声明了，但 `property::resolve` 的 `inherited` 参数在生产代码里**从没收到过非 `None` 的值**。绘制趟自己累乘绕开了它，于是**画面行为对、getter 名字不对**。 | `task-anim-wire.md` §0 |
