# 2026-10-07

## 渲染管线性能优化（第二轮）

基线 **519 µs → 162 µs（3.2×）**，每帧分配 1401 次/116 KB → **200 次/44 KB**。

| 阶段 | 起始 | 结束 |
|---|---|---|
| view | 112 µs | 41 µs |
| diff | 33 µs | 8 µs |
| paint | 105 µs | 73 µs |
| expand | 266 µs | 40 µs |

### 1. `expand` 266 → 40 µs：无裁剪快路径

细分计时（thread_local + `Instant`）显示 **Path 分支 240 µs = `expand` 的 90%**，
8 条命令 / 519 个三角形。根因：`geom_clip(_, None)` 返回 `tri.to_vec()`、
`fan_triangulate` 再 `Vec::with_capacity` —— **每个三角形两次堆分配**，
且整条链在无裁剪时是**恒等变换**。

修法：`clip_rect == None` 时直接做 NDC 变换 + 一次退化检查，零分配。

⚠ 退化检查（`signed_area2 ≈ 0` 就 `continue`）**必须留** —— 它是行为等价的一部分，
不是优化。漏掉它的症状是"看不见但占索引"的三角形进入顶点流。

**变异测试**：删退化检查 → 2 条测试失败；反转绕向 → 2 条失败。

### 2. `view` 112 → 41 µs：PropertyStore 三张 HashMap → 两个小 Vec

45 个节点 = 112 µs（2.5 µs/节点），而一个节点的属性数是**个位数**。
每节点开三张 `HashMap`（值 / 样式值 / 名字），首次 `insert` 各分配一次桶 ——
用完立刻随声明树丢掉。换成 `Vec<LocalEntry { id, name, value }>`：
三个字段打包是因为 id 与名字总是**一起**被读（diff 对账 + 判定要不要重排），
分两表就要维护一致性。`HashMap` 在这个规模还要付 `RandomState`（SipHash 初始化），
而线性扫 5 个 `usize` 分支预测器学得会。

顺带：`ElementKey::Name(Arc<str>)` → `Name(&'static str)`。
所有来源都是 `&'static str`、消费者只比内容 —— refcount 增删纯属白做。
45 节点 = 每帧 45 次 `Arc::from` 分配。（与 `PropertyValue::Resource(Arc<str>)`
**同型但不能同样处理**：那个的克隆要被多处持有，共享所有权是正当的。）

### 3. `Command::Path` 的 `vertices`：`Vec<Vertex>` → `Arc<[Vertex]>`

图标几何本来就在 `Arc` 缓存里，每帧却克隆成 `Vec` 拷一遍再当帧丢掉。
`Arc<[T]>` 的 `Deref` 让消费者的 `len`/`is_empty`/`iter`/`chunks_exact` **一字不用改**。

⚠ 中途踩过一次：`GeometryCache` 存 `Arc<TriMesh>`，而 `Arc<TriMesh>` → `Arc<[Vertex]>`
要**重新分配并 memcpy 整个数组**（胖指针得重建）—— 于是"命中缓存"反而成了最贵
那条路，与缓存的目的正好相反。改成缓存直接存 `CachedMesh { vertices: Arc<[Vertex]>, triangles }`。

### 4. `paint` 105 → 73 µs

细分显示文本链 13 节点 × 3 µs = 39 µs。`Command::Text` 的 `glyphs: Vec` **不是浪费**
（展开趟只读不拷），已确认不改。

## 本轮真正有价值的一条

**换数据结构时，最危险的 bug 是"来源对、值错"。** 我在 `PropertyStore::upsert` 里
为了省一次 clone，用两次 `mem::replace` 做"换手"，结果**旧值留在表里**。
症状：`ValueSource` 仍报 `Local`（来源对、值错），画面停在旧值 ——
**断言"来源"的测试全过，本文件原有 286 条也全过**，因为没有一条测过
"同一 key 设两次"。

补了 4 条 `store_tests`（重复设 / `new` 与表里一致 / 本地与样式互不干扰 /
按 id 与按 key 一致）。判据不是"看起来对"，是**具体值**。

## 方法论：探针会污染它自己的测量

细分探针（`thread_local` + `Instant::now()` 每节点 3 次、每三角形 1 次）
让 `paint` 从 73 µs "涨"到 107 µs、`合计` 从 162 涨到 231。
**先清探针再拿最终数据**，否则会把测量手段的开销当成回归。

三条数据都是**同一批探针**定位的，但最终数字必须在探针全清后拿 —— 这个顺序
本轮第一次做对（上一轮把探针开销当成了优化效果的一部分讨论）。

## 未做（明确判断为不值得）

- **声明树跨帧复用**（`view` 41 µs / 45 节点）：要把"重建"改成"更新"，是架构改动。
- **`PropertyValue::Resource(Arc<str>)` 去 Arc**（12 次/帧，占分配 6%）：克隆要被
  多处持有，共享所有权正当，与 `ElementKey` 不同型。
